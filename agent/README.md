# Демон делегирования задач агенту

Раз в минуту launchd запускает `run-delegation.sh`. Демон спрашивает у MCP TaskFlow очередь
(делегированные задачи на сегодня и просроченные), берёт до трёх задач, запускает для каждой
`claude --agent ai-space-assistant` и пишет результат в карточку: `review`,
`needs_info` или `failed`. Агент либо только читает и готовит черновик (`TASKFLOW_AGENT_SEND=off`),
либо ещё и отправляет в разрешённые адресаты под хуком-gate (раздел «Отправка из делегирования»). Если Mac выключен, ничего не происходит, задачи остаются `delegated`.
Нет делегированных задач: модель не вызывается вовсе.

Установка выполняется вручную, ни один скрипт и ни один тест не ставит задание на машину.

## Что нужно

- Node 18+ (демон без зависимостей).
- Работающий MCP TaskFlow (`mcp.mjs`) и сервер синхронизации (`serve.mjs`).
- `claude` и окружение `claude-paiw` (прокси, заголовки, отключённые навыки).

## Установка

1. Env-файл с правами 0600. Либо экспортируйте нужные переменные в текущей оболочке и выполните

   ```sh
   TASKFLOW_MCP_URL=http://127.0.0.1:8788/mcp TASKFLOW_MCP_TOKEN=... sh agent/setup-env.sh
   ```

   либо создайте `~/.config/taskflow-agent/env` вручную по `agent/env.example` (`chmod 700` на каталог,
   `chmod 600` на файл). Скрипт выводит только имена переменных, значения не печатаются. Обязательные
   переменные: `TASKFLOW_MCP_URL`, `TASKFLOW_MCP_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`,
   `AI_LAUNCHER_PAIW_DISABLED_ITEMS`, `CLAUDE_BIN` (абсолютный путь к `claude`). Прокси-переменные
   (`HTTP_PROXY`, `NO_PROXY`) добавьте, если их задаёт `claude-paiw`.

> **Условие установки (I07).** Plist и `launchctl bootstrap` выполняйте только после того, как в
> `openspec/changes/archive/2026-10-05-add-agent-delegation/spike-u1-u5.md` стоит `U5: PASS` (и `U1: PASS` либо принят запасной способ).
> Пока там `PENDING` или `FAIL`, задание не устанавливается: списки инструментов не сверены с реальным составом.

2. Plist из шаблона (только после `U5: PASS`):

   ```sh
   mkdir -p -m 700 ~/Library/Logs/taskflow-agent && chmod 700 ~/Library/Logs/taskflow-agent
   mkdir -p ~/Library/LaunchAgents
   sed -e "s#__REPO__#$(pwd)#g" -e "s#__HOME__#$HOME#g" agent/com.taskflow.delegation.plist.template \
     > ~/Library/LaunchAgents/com.taskflow.delegation.plist
   ```

3. Загрузка задания и пробный прогон (только после `U5: PASS`):

   ```sh
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.taskflow.delegation.plist
   launchctl kickstart -k gui/$(id -u)/com.taskflow.delegation
   tail -n 20 ~/Library/Logs/taskflow-agent/delegation.out.log
   ```

   Логи: строки JSON без текстов задач и без секретов. Код выхода 78 означает ошибку конфигурации
   (в логе имена недостающих переменных или права env-файла не 600).

## Способы запуска claude

- Основной (ADR-003): `claude --agent ai-space-assistant ...` с окружением из env-файла 0600.
  Флаги и списки инструментов собирает `agent/lib/policy.mjs` (`buildClaudeArgs()`), это единственное место.
- Запасной, только если spike U1 провалился: `zsh -ic claude-paiw ...`. Включается строкой
  `export TASKFLOW_AGENT_LAUNCH=fallback` в env-файле; токен прокси тогда берётся из вашей оболочки.

## Права инструментов

`claude` запускается с `--permission-mode dontAsk`: всё, чего нет в `--allowedTools`, отклоняется без запроса,
а не решается пользовательскими `~/.claude/settings*.json` (изменено по ревью I01). Список инструментов
только на чтение; `--disallowedTools` сверх того закрывает запись и прод. В режиме «только чтение» `--strict-mcp-config` и
`--setting-sources` намеренно не используются (могут отрезать агента `ai-space-assistant`), этот режим не менялся.
Открытый пункт: spike проверяет, что инструменты вне allow недоступны. Режим с отправкой устроен иначе: см. «Серверы MCP в режиме отправки».

Локальная файловая система закрыта целиком (security SEC01): в `--disallowedTools` входят `Read`, `Glob`, `Grep`,
`LS`, `NotebookRead`, `TodoWrite`, `Bash`, `Write`, `Edit`, `NotebookEdit`. Иначе под prompt injection агент мог бы прочитать
`~/.config/taskflow-agent/env` или `~/.ssh` и записать это в заметки агента (они неудаляемы и синхронизируются).
`Skill` и `Agent` оставлены в `--allowedTools` сознательно: `ai-space-assistant` делегирует субагентам через `Agent`.
Защита здесь — deny имеет приоритет над `allowed-tools` навыков и субагентов, плюс `dontAsk`; spike (пункт U5) проверяет,
что субагент через `Agent` наследует deny.

Рабочий каталог процесса `claude` — пустая песочница `~/.local/state/taskflow-agent/work` (создаётся с режимом 0700,
права проверяются при каждом запуске). `TASKFLOW_AGENT_CWD` может её переопределить, но не на домашний каталог (exit 78).
Окружение процесса — белый список: `PATH`, `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_*`, `TMPDIR`, `TERM`, `SHELL`, `ANTHROPIC_*`,
`AI_LAUNCHER_PAIW_*`, `HTTP(S)_PROXY`, `NO_PROXY` (оба регистра), `CLAUDE_CODE_*`, `CLAUDE_CONFIG_DIR`. `TASKFLOW_*` не передаются никогда;
в запасном `zsh -ic` они дополнительно снимаются после загрузки `.zshrc`. Повторный SIGTERM/SIGINT демону убивает группу
процессов claude (SIGKILL) и завершает демон сразу.

## Проверка запуска (spike U1 и U5)

Запускает пользователь, из корня репозитория. Временные serve/mcp с синтетической задачей и одно
временное задание launchd, всё удаляется при выходе; реальные данные и VPS не затрагиваются.
Каждый прогон `claude` ограничен бюджетом 1.00 USD.

```sh
SPIKE_MODE=env SPIKE_OUT="$HOME/Library/Logs/taskflow-spike" sh agent/spike/run-spike.sh
# если не заработало: проверка запасного способа
SPIKE_MODE=fallback SPIKE_OUT="$HOME/Library/Logs/taskflow-spike-fb" sh agent/spike/run-spike.sh
```

Вердикты (`U1`, `U5`, `SRC-35`) занесите в `openspec/changes/archive/2026-10-05-add-agent-delegation/spike-u1-u5.md`.

## Отправка из делегирования

В режиме с отправкой агент может писать в VK Teams, комментировать MR и Jira и создавать страницы Confluence.
Постановка делегированной задачи считается явным запросом, превью и подтверждения нет. Остановить отправку
вне списка может только gate (хук `PreToolUse` из `--settings`, `agent/hooks/send-gate.mjs`): шесть инструментов
отправки не входят ни в `--allowedTools`, ни в `--disallowedTools`, их открывает только его ответ `allow`.
Письма, календарь, создание чатов, участники, resolve, merge, удаления, правка существующих страниц, Bash,
чтение файлов и kubernetes остаются в deny.

### Включение и выключение

- Переменная `TASKFLOW_AGENT_SEND` в env-файле: **отправка включена только при `on`** (opt-in). Без переменной, с `off`,
  пустой строкой, `ON` или опечаткой демон остаётся в режиме «только чтение». `agent/env.example` поставляется со строкой
  `TASKFLOW_AGENT_SEND=off`: ставьте `on` только после спайков S1 и S3 (без `S1: PASS` и `S3: PASS` в `spike-s1-s3.md` демон
  при `on` пишет в лог предупреждение `send_spikes_not_passed`). `setup-env.sh` переносит существующее значение переменной.
  Включённая отправка с пустыми списками блокирует всё; перед стартом демон проверяет пользовательские настройки claude
  (`~/.claude/settings*.json`, настройки песочницы): правило allow, открывающее инструмент отправки, его сервер, `*` или `mcp__*`,
  даёт `config_error` (код 78), значения правил в лог не попадают.
- Выключатель: `export TASKFLOW_AGENT_SEND=off` в env-файле и `launchctl kickstart -k gui/$(id -u)/com.taskflow.delegation`.
- Аварийная процедура без перезапуска: очистите списки в `send-policy.json` (оставьте `"allow": {}`). Gate читает файл заново
  на каждом вызове, так что со следующей отправки всё блокируется.

### Файл политики

Путь по умолчанию `~/.config/taskflow-agent/send-policy.json` (переопределяется `TASKFLOW_AGENT_SEND_POLICY`). Шаблон лежит в
`agent/send-policy.example.json`. Файл должен быть обычным файлом (не симлинком), принадлежать вам, иметь права `0600`
(любой бит группы или остальных, а также исполнение владельца — отказ) и быть не больше 64 КиБ. Gate при любой ошибке чтения
блокирует вызов.

```json
{ "version": 1,
  "allow": { "vk_chats": [], "gitlab_projects": [], "jira_projects": [], "confluence_spaces": [] },
  "limits": { "vk": 3, "gitlab_comment": 20, "jira": 3, "confluence": 2 } }
```

**Пустой белый список блокирует любое действие**: задача уходит в `review` с пометкой «не всё выполнено», готовый текст остаётся
в результате. Список не больше 200 значений, неизвестные ключи отвергаются. Потолки в файле можно только уменьшить: значения выше
дефолтов (3 сообщения VK Teams, 20 комментариев GitLab, 3 комментария Jira, 2 страницы Confluence на запуск) сводятся к дефолту.
Потолок общий для агента и его субагентов и не возвращается после ошибки.

### Что писать в белый список

Значения сравниваются точно, без обрезки пробелов и смены регистра. Проще всего скопировать их из карточки: заблокированная попытка
попадает в журнал строкой `заблокировано (адресат вне списка) · VK Teams → чат <chat_sn>`. Значение после «чат» идёт в `vk_chats`;
для GitLab это `project_id` в том виде, как его передал агент (число или путь `group/project`), для Jira ключ проекта (`VKTAI`
из `VKTAI-123`), для Confluence ключ пространства. Точный вид `project_id` и `chat_sn` подтверждает спайк S1.

### Журнал в карточке

После прогона в заметке агента первым блоком стоит «Журнал действий (срок …)»: что выполнено (со ссылкой), заблокировано, упало
или начато без подтверждённого итога. Журнал строится из аудита хука, текст модели на него не влияет. Строка «Не всё выполнено»
над блоком считается из журнала. Задача остаётся открытой (`review`), закрываете её вы обычной галкой; отправки по галке нет.
Если процесс зависает, журнал берётся из каталога прогона (`~/.local/state/taskflow-agent/runs/`, права 0700, хранение 14 дней).

### Повтор и прежние попытки

Если задача возвращается в очередь с тем же сроком, агент получает журналы прежних попыток (не больше трёх, как данные) и не повторяет
выполненное. Запись «начато, итог не подтверждён» значит, что сообщение могло уйти: агент его не повторяет, проверить нужно вручную.
Журналы с другим сроком не передаются.

### Порядок раскатки

Сначала сервер (`serve.mjs`, `mcp.mjs`: необязательные `journal` в `agent_finish` и `journals` в `agent_claim`), затем демон.
Демон в режиме с отправкой, получив ответ `agent_claim` без `journals`, не запускает `claude`
и пишет `failed` «Сервер не поддерживает журнал действий».

### Серверы MCP в режиме отправки

В режиме с отправкой `claude` запускается с `--strict-mcp-config --mcp-config <runDir>/mcp.json` и поднимает **только** четыре сервера:
`mcp-workspace-assistant`, `mcp-jira`, `mcp-confluence`, `generic:gitlab` (список `SEND_MCP_SERVERS` в `agent/lib/mcp-config.mjs`).
Плагины, коннекторы claude.ai, `yadisk`, `telegram`, `kubernetes` и всё остальное не загружаются вовсе. Причина: спайк S1 (к) показал,
что deny-префикс `mcp__plugin_` в Claude Code не работает, а allow-правило на плагинный сервер в настройках открывает его инструмент.
Preflight SEC13 (отказ на allow `mcp__plugin_*`) и deny-списки остаются как вторая линия.

- Описания серверов копируются дословно из user-scope `mcpServers` файла `$CLAUDE_CONFIG_DIR/.claude.json` (если задан в env демона, иначе `~/.claude.json`);
  других ключей файла (учётка, проекты) не берётся. Ключ `generic:gitlab` не переименовывается: Claude Code сам нормализует его в `mcp__generic_gitlab__*`.
- Нет файла, он нечитаем или битый, либо нет ни одного из четырёх серверов: `config_error`, демон выходит с кодом 78 до захвата задач.
  Нет отдельных серверов из четырёх: прогон идёт с остальными, в лог попадают только их имена (`mcp_servers_missing`, `mcp_config`).
- **Новый сервер для агента**: добавьте его ключ в `SEND_MCP_SERVERS` (и инструменты в списки `agent/lib/policy.mjs`); иначе он агенту не виден.
- `mcp.json` содержит токены серверов: создаётся с флагом `wx` и правами 0600 в каталоге прогона (0700), путь передаётся флагом, содержимое
  в argv (видно в `ps`) и в логи не попадает; значения `env` и `headers` скопированных серверов редактируются в хвосте stderr.
  Файл удаляется сразу после завершения `claude` на любом пути: нормальный выход, таймаут, закрытие задачи (abort), SIGTERM/SIGINT демона
  (первый сигнал останавливает группу, затем `finally`; повторный удаляет файлы синхронно до выхода), ошибка запуска. После SIGKILL демона
  остаток убирает sweep при следующем старте (под замком) и очистка каталогов прогона.

### Известные ограничения

- Адресат сверяется по значению как есть (SEC05): алиасы и разные записи одного и того же чата или проекта (путь и числовой id) gate не склеивает; в списке нужна именно та форма, в которой агент передаёт значение.
- Суточного счётчика нет (SEC06): потолки действуют на один прогон.
- После прерывания прогона (таймаут, остановка демона, перезапуск) проверьте отправленное вручную: журнал строится из аудита хуков, и запись `начато, итог не подтверждён` означает, что отправка могла дойти.
- Тела комментариев MR и сообщений VK с командой в начале строки (`/merge`, `/approve`, ...) блокируются (причина «быстрое действие в тексте»), как и макросы Confluence `html`, `iframe`, `include`, `html-include`. Перед `/` допускаются пробелы, управляющие и невидимые символы (U+200B, U+00AD, NUL ...): они тоже считаются началом строки.
- SEC14: макросы Confluence `html`, `iframe`, `include`, `html-include`, записанные через HTML-сущности или нестандартные атрибуты, regexp не распознаёт. Проверка по имени макроса остаётся эвристикой; список разрешённых пространств Confluence сужает риск.
- Preflight настроек (SEC02, SEC12, SEC13) читает `$CLAUDE_CONFIG_DIR` (или `~/.claude`), настройки песочницы и managed-файлы (`/Library/Application Support/ClaudeCode/managed-settings.json`, `managed-settings.d/*.json`); allow-правило на send-инструмент (точное имя, префикс сервера, glob `*`, хвост `(...)` срезается) или на `mcp__plugin_*` отклоняет запуск.

### Спайки S1..S3

Перед `TASKFLOW_AGENT_SEND=on` запустите `agent/spike/send/run-s1.sh` и `run-s3.sh` (S2, `run-s2.sh`, уточняет лимиты и форму `Agent(<имя>)`).
Они идут на заглушке MCP с настоящими именами инструментов, реальных отправок нет; вердикты вносятся в
`openspec/changes/archive/2026-10-06-agent-send-actions/spike-s1-s3.md`. Если `S1` не прошёл (пункт б: `allow` хука не открывает инструмент вне
`--allowedTools`), отправка не включается, решение возвращается к вам.

## Смена токена

Токен MCP или прокси сменился: пересоздайте env-файл (шаг 1) и выполните
`launchctl kickstart -k gui/$(id -u)/com.taskflow.delegation`.

## Откат

```sh
launchctl bootout gui/$(id -u)/com.taskflow.delegation
rm ~/Library/LaunchAgents/com.taskflow.delegation.plist
rm -rf ~/.config/taskflow-agent ~/.local/state/taskflow-agent
```

Делегированные задачи остаются в списке как есть; зависший `in_progress` через 20 минут сервер
переведёт в `failed` при следующем прогоне любого экземпляра демона либо снимите делегирование
галкой в карточке.

## Лимиты

Интервал 1 минута (пустая очередь проверяется без модели и ничего не стоит), до 3 задач за прогон последовательно, таймаут задачи 15 минут, `--max-turns 30`
и `--max-budget-usd 2.00` (в режиме с отправкой 50 и 3.00), опрос статуса раз в минуту (закрытие задачи останавливает процесс),
остановка SIGTERM, через 10 секунд SIGKILL. Автоповторов нет.

## Известные ограничения

- SEC03 (частично): в интерфейсе заметки агента показываются текстом, без кликабельных ссылок. `task_get` в `mcp.mjs`
  не менялся (контракт NFR-007/SRC-33), поэтому интерактивный клиент получает текст заметок как есть.
- CR-I03: при восстановлении задачи на чистом сервере метка журнала (`kind: 'journal'`) снимается, такие блоки не попадают в `previous_attempts`.
- SEC10: у веб-приложения нет Content-Security-Policy. Заголовок можно добавить в `serve.mjs`, но он требует проверки
  инлайн-стилей и service worker; пока не сделано.

- I07 (`agent/lib/lock.mjs:29-43`, race condition): захват stale-замка неатомарен. Два процесса, увидевшие мёртвый pid, могут оба сделать `rmSync(dir)`; второй сотрёт только что созданный каталог первого, и оба получат замок. Если pid мёртвого держателя переиспользован, замок считается живым бесконечно. При одном экземпляре launchd риск низкий. Возможное улучшение: атомарный `rename` каталога перед `mkdir` и сверка времени старта процесса.
- I10 (`mcp.mjs`, безопасность): служебные инструменты `agent_queue`/`agent_claim`/`agent_finish` видны любому MCP-клиенту с токеном, защита только текстом `description`. Интерактивная сессия может вызвать claim/finish, но только при совпадении claim-токена и состояния. Для демона `mcp__taskflow` закрыт в deny.
