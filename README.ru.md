# TaskFlow

Личный менеджер задач одной HTML-страницей: приоритеты по матрице Эйзенхауэра,
повторяющиеся задачи, планирование дня («Moments») и синхронизация между
устройствами. Без бэкенда, без сборки, без зависимостей — статика, которую
можно положить на любой хостинг и открыть с Mac и с iPhone.

*(English summary at the bottom.)*

---

## Что умеет

- **Разделы:** Сегодня (вместе с просроченным), Входящие, Завтра, Ближайшие (по дням), Все, Выполнено.
- **Входящие** — плоский список неразобранного: без даты и без приоритета. Сюда попадает всё, чему ещё не назначен день, — задача, созданная без даты, задача, у которой дату сняли, и то, что кладёт агент. Разбор — при планировании в Moments или прямо на карточке: «В задачу» или «Отбросить».
- **Задача:** название, заметки, подзадачи с галочками.
- **Ссылки кликабельны:** адрес в названии задачи или в заметках остаётся на своём месте в тексте и просто становится кликабельным — в строке списка, в карточке задачи и в карточке планирования дня. Открывается в новой вкладке; в списке нажатие на ссылку не открывает карточку и не начинает перетаскивание. Нажатие на заметки мимо ссылки открывает правку, причём курсор встаёт туда, куда нажали.
- **Готово / вернуть в работу**, кнопка «Очистить выполненные» с возможностью отмены.
- **Дата и время напоминания:** быстрые кнопки «Сегодня / Завтра / Через 2 дня / Следующая неделя» и обычные поля даты и времени.
- **Повторы:** ежедневно, еженедельно, ежемесячно, с интервалом и временем. Отметили «сделано» — задача сама переезжает на следующую дату серии, подзадачи сбрасываются.
- **Приоритеты:** P1 срочно и важно, P2 важно и не срочно, P3 срочно и не важно, P4 не важно и не срочно.
- **Перетаскивание:** задачу можно тянуть за любое место строки. Мышью — просто потяните; пальцем — задержите на строке, и она «оторвётся» (короткий свайп остаётся прокруткой списка). Ручка `⠿` справа берёт строку сразу, без удержания. Внутри группы — меняется порядок, между группами — дата: бросили в «Завтра» — задача переехала на завтра, а чтобы вернуть задачу во «Входящие», достаточно снять дату в карточке. Работает и с клавиатуры: `Tab` до ручки, дальше `↑` / `↓`.
- **Порядок списка:** по умолчанию автоматический (по времени, затем по приоритету). Первое же перетаскивание закрепляет ручной порядок; кнопка `⇅` в шапке (или клавиша `s`) переключает режимы обратно.
- **Moments** — планирование дня: приложение проводит по одной очереди — сначала неразобранные входящие, потом задачи (просроченные и сегодняшние), — и для каждой спрашивает приоритет и когда делать: сегодня (утро / обед / день / вечер), завтра, через 2 дня, на следующей неделе. Ответ на «когда» превращает входящее в задачу; последняя кнопка оставляет входящее неразобранным, а задачу возвращает во «Входящие». Плюс «уже сделано» и «не актуально».
- **Локальные напоминания** — пока вкладка или установленное приложение открыты.
- **Тема** — светлая, тёмная, как в системе.
- **Синхронизация между устройствами** — задачи хранятся на вашем сервере, и Mac, iPhone и любой браузер видят один список. Работает офлайн: правки копятся локально и уезжают, когда появляется сеть.
- **Доступ для агента** — отдельный MCP-сервер даёт Claude Code и другим MCP-клиентам те же операции над задачами плюс работу со «Входящими» (свой токен, отдельный от синхронизации).
- **Данные** — ваши и только ваши: свой сервер плюс локальная копия в браузере. Экспорт и импорт JSON для резервной копии.

**Добавление задачи.** Поля ввода над списком нет: главная страница — сразу
список. Новая задача заводится кнопкой «+» в правом нижнем углу или клавишей `n` —
и то и другое открывает одно и то же окно быстрого ввода. Окно не закрывается
после Enter: поле очищается, курсор остаётся в нём, и подряд можно занести
сколько угодно задач. Дата по умолчанию берётся из раздела, из которого окно
открыли (во «Входящих» и в «Выполнено» — без даты, то есть во «Входящие»).

Быстрый ввод понимает подсказки: `Купить молоко завтра 18:30 !1` → задача на завтра
в 18:30 с приоритетом P1. Понимаются `сегодня`, `завтра`, `послезавтра`, время `ЧЧ:ММ`
и `!1`…`!4`.

Горячие клавиши: `n` — новая задача, `m` — Moments, `s` — порядок списка, `,` — настройки, `1`…`6` — разделы (`1` — Сегодня, `5` — Входящие).

## Запуск локально

```bash
git clone <ваш-репозиторий> taskflow
cd taskflow
node serve.mjs          # http://localhost:8787
```

Нужен Node 18+. При первом запуске создаётся каталог `data/` и печатается токен
синхронизации — его нужно вставить в **Настройки → Синхронизация между устройствами**
в каждом браузере, который должен видеть общий список:

```
TaskFlow → http://127.0.0.1:8787
Данные: /path/to/taskflow/data
Токен синхронизации: H5are3dTiFGZq_1uRphwwZX2vQc9oNY4
```

Токен лежит в `data/token.txt`; переменная `TASKFLOW_TOKEN` его переопределяет.
По умолчанию сервер слушает только `127.0.0.1` — наружу он не торчит, пока вы
явно не зададите `HOST=0.0.0.0`.

Без сервера приложение тоже открывается (это статика), но синхронизация будет
недоступна, и задачи останутся в одном браузере.

> Открывать `index.html` двойным кликом (`file://`) не стоит: ES-модули и
> service worker в этом режиме браузеры блокируют.

## Синхронизация между устройствами

Приложение хранит задачи в двух местах сразу:

- **на сервере** — `data/taskflow.json`, общий для всех устройств;
- **в браузере** — `localStorage`, локальная копия, благодаря которой всё
  работает офлайн.

Обмен идёт слиянием, а не перезаписью: каждое устройство отправляет своё
состояние целиком, сервер сливает его с общим и возвращает результат.
При расхождении побеждает более свежая правка — сравниваются метки `updatedAt`
у задач. Удаления хранятся как «надгробия» (`{id, at}`) в течение 30 дней: без
них задача, удалённая на Mac, вернулась бы обратно при первом же обмене с iPhone,
который о её удалении ещё не знает. Если задачу поправили **позже** удаления,
слияние считает это осознанным возвратом и восстанавливает её.

Обмен запускается при открытии приложения, при возврате на вкладку, при
появлении сети, раз в минуту в фоне и по кнопке `☁` в шапке. Правки уходят
пачкой через секунду после последнего изменения, а не по одной.

**Настройки синхронизируются? Нет.** Тема и порядок сортировки остаются
локальными для каждого устройства — синхронизируются только задачи.

### Доступ к API

| Метод | Путь | Назначение |
|-------|------|-----------|
| `GET`  | `/api/ping`  | проверка, что сервер синхронизации вообще есть (без токена) |
| `GET`  | `/api/state` | текущее общее состояние |
| `POST` | `/api/sync`  | слить присланное состояние с общим и вернуть результат |

Всё, кроме `/api/ping`, требует заголовок `Authorization: Bearer <токен>`.
Токен сравнивается за постоянное время, каталог `data/` статикой не отдаётся.

## Доступ для агента (MCP)

Рядом с основным сервером может работать второй процесс — `mcp.mjs`. Он говорит
по [Model Context Protocol](https://modelcontextprotocol.io) и даёт агенту
(Claude Code и любому другому MCP-клиенту) те же операции над задачами, что есть
в приложении:

| Инструмент | Что делает |
|---|---|
| `tasks_list` | список задач раздела: `today`, `tomorrow`, `upcoming`, `all`, `done`, `overdue` |
| `task_get` | одна задача целиком: заметки, подзадачи, повтор |
| `task_add` | создать задачу за один вызов: срок, приоритет, заметки, подзадачи, повтор |
| `task_edit` | изменить поля; `clear_due` снимает срок вместе с повтором |
| `task_snooze` | перенести срок; время суток сохраняется |
| `task_done` | отметить выполненной или вернуть в работу; повторяющаяся уезжает на следующую дату серии |
| `subtask_add` | добавить подзадачу |
| `subtask_toggle` | переключить готовность подзадачи |
| `task_delete` | удалить задачу — только с `confirm: true` |
| `inbox_list` | неразобранные входящие: источник, выжимка агента, время |
| `inbox_add` | положить входящее: `title`, `summary`, `source_kind`, `source_url`, `source_title`, `source_ref` |
| `task_comment` | дописать контекст в ленту `agentNotes` задачи или входящего |

Задачу можно называть словами: `task: "молоко"` найдёт её по названию. Если
подходит несколько — инструмент вернёт список кандидатов и **ничего не изменит**.
Сроки тоже понимаются словами: `сегодня`, `завтра`, `послезавтра`, `понедельник`,
`+3`, `2026-09-15`, `завтра 18:30`.

### Что агенту можно во «Входящих»

Агент наполняет «Входящие» **только по просьбе или по явно оговорённым правилам
разбора** — сам, по своему усмотрению, он туда ничего не кладёт.

В «Входящие» едет сырьё: заголовок, выжимка и ссылка на источник — **без даты и
без приоритета**. Планирует человек, при разборе. `inbox_add` дату и приоритет
не принимает вовсе, а `task_add` без даты создаёт входящее, а не задачу.

Повторный `inbox_add` с тем же `source_ref` (для письма — `Message-ID`, для
телеграма — `chat_id:message_id`) обновляет существующую запись, а не заводит
вторую. Выжимка агента попадает в ленту `agentNotes` — поле `notes`, куда пишет
человек, агент не трогает ни здесь, ни в `task_comment`.

Запуск:

```bash
npm install             # единственная зависимость — @modelcontextprotocol/sdk
node mcp.mjs            # http://127.0.0.1:8788/mcp
```

Для `mcp.mjs` нужен Node 20+ (требование SDK); самому приложению и `serve.mjs`
по-прежнему хватает Node 18.

`node serve.mjs` при этом по-прежнему работает без `npm install`: SDK нужен
только файлу `mcp.mjs`, и импортируется он динамически.

При старте печатается токен и готовая строка подключения:

```
TaskFlow MCP → http://127.0.0.1:8788/mcp
Основной сервер: http://127.0.0.1:8787
Токен MCP: 8Kx2n5Qw...
Подключение: claude mcp add --transport http taskflow http://127.0.0.1:8788/mcp --header "Authorization: Bearer 8Kx2n5Qw..."
```

**Токен у MCP свой, отдельный от токена синхронизации.** Синхронизационный вбит
в браузеры на Mac и iPhone; MCP-токен лежит в `data/mcp-token.txt` и
переопределяется переменной `TASKFLOW_MCP_TOKEN`. Удалите файл и перезапустите
`mcp.mjs` — агент отключится, браузеры ничего не заметят.

Файл с задачами `mcp.mjs` не трогает: читает через `GET /api/state`, пишет через
`POST /api/sync` — ровно как ещё одно устройство. Хозяин у файла один,
`serve.mjs`, а правки агента сливаются по тем же правилам, что и правки с телефона.

Переменные окружения: `PORT` (8788), `TASKFLOW_API` (адрес основного сервера),
`TASKFLOW_DATA`, `TASKFLOW_MCP_TOKEN`, `TASKFLOW_TOKEN`, `TASKFLOW_MCP_ORIGINS`
(дополнительные допустимые `Origin` через запятую).

### Почему Bearer-токен, а не OAuth 2.1

Спецификация MCP для HTTP-транспорта предлагает авторизацию по OAuth 2.1.
Здесь она сознательно не используется: это инструмент на одного человека, и
authorization server, регистрация клиента и refresh-токены — лишний слой ради
доступа к собственному списку дел.

Вместо этого — Bearer-токен со сравнением за постоянное время (как уже сделано
в `sync.mjs`), прослушивание только `127.0.0.1` и проверка заголовка `Origin`
(прямая рекомендация спецификации против DNS rebinding); наружу порт выводит
Caddy по HTTPS. Отклонение записано здесь намеренно: если появится второй
пользователь или сторонний клиент, к этому решению придётся вернуться — и тоже
осознанно.

## Развёртывание на VPS

Для доступа с iPhone нужен HTTPS-адрес: `localhost` с телефона недоступен,
а PWA и уведомления без HTTPS не работают.

### 1. Сервис

Скопируйте репозиторий в `/var/www/taskflow` и заведите systemd-юнит
`/etc/systemd/system/taskflow.service`:

```ini
[Unit]
Description=TaskFlow
After=network.target

[Service]
Type=simple
User=taskflow
WorkingDirectory=/var/www/taskflow
Environment=PORT=8787
Environment=TASKFLOW_DATA=/var/lib/taskflow
ExecStart=/usr/bin/node serve.mjs
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -s /usr/sbin/nologin taskflow
sudo mkdir -p /var/lib/taskflow && sudo chown taskflow: /var/lib/taskflow
sudo systemctl enable --now taskflow
sudo journalctl -u taskflow | grep Токен      # понадобится для настроек
```

Держать данные в `/var/lib/taskflow`, а не внутри каталога с кодом, стоит
затем, чтобы обновление кода не задевало задачи.

### 2. HTTPS

Caddy сам получает сертификат Let's Encrypt и проксирует всё на Node:

```caddyfile
tasks.example.com {
    encode gzip
    reverse_proxy 127.0.0.1:8787
}
```

Вариант на nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name tasks.example.com;

    ssl_certificate     /etc/letsencrypt/live/tasks.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tasks.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
    }
}
```

Статику теперь тоже отдаёт Node — отдельный `root` не нужен, иначе `/api`
окажется недоступным.

### 3. Подключение устройств

Откройте `https://tasks.example.com` на Mac и на iPhone, вставьте один и тот же
токен в **Настройки → Синхронизация между устройствами** → «Подключить».
На iPhone добавьте приложение на экран «Домой» (Safari → «Поделиться» →
«На экран Домой»).

### 4. MCP-сервер (необязательно)

Нужен, только если к списку задач ходит агент. Отдельный юнит
`/etc/systemd/system/taskflow-mcp.service`:

```ini
[Unit]
Description=TaskFlow MCP
After=network.target taskflow.service
Wants=taskflow.service

[Service]
Type=simple
User=taskflow
WorkingDirectory=/var/www/taskflow
Environment=PORT=8788
Environment=TASKFLOW_API=http://127.0.0.1:8787
Environment=TASKFLOW_DATA=/var/lib/taskflow
ExecStart=/usr/bin/node mcp.mjs
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
cd /var/www/taskflow && sudo -u taskflow npm install
sudo systemctl enable --now taskflow-mcp
sudo journalctl -u taskflow-mcp | grep Подключение   # готовая строка для клиента
```

`/mcp` уходит на другой порт, поэтому в Caddy маршрут описывается отдельно и
**до** общего:

```caddyfile
tasks.example.com {
    encode gzip
    handle /mcp* {
        reverse_proxy 127.0.0.1:8788
    }
    handle {
        reverse_proxy 127.0.0.1:8787
    }
}
```

Подключение клиента к серверу — тот же токен, но по HTTPS-адресу:

```bash
claude mcp add --transport http taskflow https://tasks.example.com/mcp \
  --header "Authorization: Bearer <токен из journalctl>"
```

### Старый вариант: только статика

Если синхронизация не нужна, файлы по-прежнему можно раздать как статику —
приложение это переживёт и будет хранить задачи локально:

```nginx
server {
    listen 80;
    server_name tasks.example.com;

    root /var/www/taskflow;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # Приложение обновляется целиком, поэтому оболочку не кешируем надолго
    location = /sw.js        { add_header Cache-Control "no-cache"; }
    location = /index.html   { add_header Cache-Control "no-cache"; }
}
```

Синхронизации в этом варианте не будет: без `/api` приложение работает так же,
как раньше, — каждый браузер сам по себе.

### HTTPS обязателен для PWA

По голому `http://` работают задачи, приоритеты, повторы, Moments, синхронизация
и локальное хранение. **Не будут работать:** service worker, установка на
домашний экран, уведомления. То есть на iPhone без HTTPS приложение открыть
можно, но поставить на экран «Домой» — нет.

Самый короткий путь к сертификату — Caddy: он получает Let's Encrypt сам,
конфиг из шага «HTTPS» выше состоит из двух строк.

## Установка как приложение

Нужен HTTPS (или `http://localhost`).

- **iPhone / iPad:** Safari → «Поделиться» → **На экран «Домой»**. Откроется без адресной строки, с иконкой.
- **macOS Safari:** «Файл» → **Добавить в Dock**.
- **Chrome / Edge:** значок установки в адресной строке → «Установить».

Каждая установка — отдельное хранилище браузера, поэтому после установки
вставьте токен в **Настройки → Синхронизация между устройствами**, иначе
приложение начнёт с пустого списка.

## Хранение и перенос данных

При включённой синхронизации главный экземпляр списка — `data/taskflow.json`
на сервере; его и надо класть в резервную копию. В каждом браузере остаётся
локальная копия в `localStorage`, поэтому очистка данных сайта задачи не потеряет:
при следующем обмене они вернутся с сервера.

Без синхронизации всё лежит только в `localStorage` того браузера, где вы
работаете. Перенести список можно через **Настройки → Данные → Экспорт JSON**
и **Импорт JSON** на другом устройстве (объединение по времени изменения или
полная замена).

## Структура проекта

```
index.html              разметка оболочки
styles.css              тема, вёрстка, адаптив
js/core.js              даты, повторы, форматирование — общее для браузера и сервера
js/dom.js               DOM-хелперы
js/store.js             состояние, localStorage, экспорт/импорт
js/model.js             задачи: CRUD, повторы, выборки для разделов, ручной порядок
js/ui.js                отрисовка, перетаскивание, редактор задачи, настройки
js/moments.js           мастер планирования дня
js/sync.js              обмен с сервером синхронизации, слияние ответа
js/app.js               точка входа, маршрутизация, горячие клавиши, напоминания
sw.js                   офлайн-кеш оболочки
serve.mjs               сервер: статика + /api
sync.mjs                хранилище задач на сервере и правила слияния
mcp.mjs                 MCP-сервер для агента (нужен npm install)
package.json            единственная зависимость — MCP SDK, только для mcp.mjs
data/                   задачи и токен (создаётся при первом запуске, в git не попадает)
manifest.webmanifest    манифест PWA
```

Формат даты внутри приложения — локальная наивная строка: `2026-08-19` (весь день)
или `2026-08-19T18:30` (со временем). Часовой пояс не хранится: задача на 18:30
остаётся задачей на 18:30 в том поясе, где вы её открыли.

Ручной порядок хранится в поле `order` задачи. Пока включён автоматический режим,
поле не используется; при первом перетаскивании текущий порядок списка
записывается в `order`, чтобы ничего не прыгнуло, и дальше он главный.
Перетаскивание сделано на Pointer Events, а не на HTML5 drag-and-drop, —
иначе оно не работало бы на тач-экранах. Тянуть можно за всю строку, но она уже
занята кликом (открыть задачу) и вертикальным свайпом (прокрутить список),
поэтому намерение определяется по способу ввода: мышь начинает перетаскивание
после сдвига на 5 px, палец — только после удержания в 350 мс.

## English

TaskFlow is a dependency-free, single-page task manager you can host as static
files: Eisenhower priorities, subtasks, recurring tasks, a daily planning wizard
("Moments"), drag-and-drop reordering (drag a task onto another group to
reschedule it). Tasks sync
across devices through a small dependency-free Node backend (`serve.mjs` +
`sync.mjs`, single JSON file, bearer token): every device merges its full state
into the server's, last write wins per task, and deletions are kept as 30-day
tombstones so they do not come back. Each browser keeps a `localStorage` copy, so
the app works offline and catches up when the network returns. PWA install
requires HTTPS (or `http://localhost`) — see the deployment section above.
An optional MCP server (`mcp.mjs`, one dependency) exposes the same task
operations to AI agents over Streamable HTTP with its own bearer token.
Run locally with `node serve.mjs`. MIT licensed.
