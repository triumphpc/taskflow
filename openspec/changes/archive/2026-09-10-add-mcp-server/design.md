## Context

TaskFlow держится на правиле «запускается одной командой»: `node serve.mjs`, без сборки,
без `npm install`, без зависимостей. Браузерная часть — ES-модули, которые браузер грузит
как есть.

Данные живут в `data/taskflow.json`. Запись сериализована цепочкой промисов внутри
`SyncStore` — но только в пределах одного процесса. Второй процесс, пишущий в тот же файл,
сломает это гарантированно: `read-modify-rename` из двух мест — классическая гонка с потерей
записи.

Агентский контур сегодня — `tf.py`, 509 строк Python в **другом** репозитории
(`~/Devel/agents-ensemble/skills/taskflow/`, симлинк из `~/.claude/skills/taskflow`).
Он ходит в те же `GET /api/state` и `POST /api/sync`, что и браузер.

Работа идёт после удаления Google Calendar: тот change расчищает `js/ui.js`, этот трогает
импорты во всех модулях сразу.

## Goals / Non-Goals

**Goals:**

- Сделать список задач сервисом, доступным любому MCP-клиенту по адресу и токену.
- Развести права: отзыв доступа агенту не должен трогать телефон и Mac.
- Свести правила дат к одной копии вместо двух.
- Сохранить правило «`node serve.mjs` работает без `npm install`».

**Non-Goals:**

- Многопользовательский доступ, роли, OAuth. Инструмент на одного человека.
- Режим только для чтения (отдельный токен без права писать) — отложено до появления
  сценария, где он нужен; см. «Open Questions».
- Серверные уведомления (`GET /mcp` по SSE) — слать пока нечего.
- Изменение протокола синхронизации и формата данных.

## Decisions

### Решение 1: Отдельный процесс, а не маршрут внутри `serve.mjs`

`mcp.mjs` живёт своим процессом на порту 8788.

```
Claude Code / OpenCode
        │  HTTPS, Bearer <mcp-token>
        ▼
   Caddy  /mcp*  ──►  mcp.mjs  :8788
        │                 │  HTTP, Bearer <sync-token>
        │                 ▼
        └────  /*  ──►  serve.mjs :8787  ──►  data/taskflow.json
```

Альтернатива — вкрутить `/mcp` прямо в `serve.mjs`: на один процесс меньше, не нужен маршрут
в Caddy и второй systemd-юнит. Отвергнута, потому что тогда `@modelcontextprotocol/sdk`
попадает в основной сервер и `node serve.mjs` перестаёт запускаться без `npm install`.
Правило «поднимается одной командой» дороже сэкономленного юнита.

Побочная выгода — изоляция: смена транспорта в спеке MCP (Streamable HTTP уже заменил
HTTP+SSE в 2025 году) потребует обновить один файл, не трогая приложение.

### Решение 2: MCP-сервер — клиент HTTP API, а не второй владелец файла

`mcp.mjs` не открывает `data/taskflow.json`. Читает `GET /api/state`, пишет `POST /api/sync`
тем же способом, что браузер и `tf.py`.

Владелец файла остаётся один — `serve.mjs`, — и гонка на read-modify-rename не возникает
конструктивно, а не благодаря аккуратности.

Альтернатива — прямой доступ к файлу с файловой блокировкой. Отвергнута: блокировки поверх
`rename` переносимы плохо, а выигрыш (один сетевой хоп по петле) неизмерим на личном списке дел.

### Решение 3: Bearer-токен вместо OAuth 2.1

Спека MCP для HTTP-транспорта предлагает OAuth 2.1. Для инструмента на одного пользователя
это лишний слой: authorization server, регистрация клиента, refresh-токены — ради доступа
одного человека к своему списку дел.

Берём Bearer-токен, сравнение в постоянное время (как уже сделано в `sync.mjs`), слушаем
только `127.0.0.1`, проверяем `Origin` — прямая рекомендация спеки против DNS rebinding.
Наружу выводит Caddy.

Отклонение записывается в `README` явным абзацем: решение осознанное, и пересматривать его
надо тоже осознанно.

### Решение 4: `js/util.js` режется на `js/core.js` и `js/dom.js`

`js/util.js` (260 строк) смешивает несвязанное: обёртки над DOM (`$`, `$$`, `h`, `append`,
`clear`, `linkify`, `findLinks`, `caretIndexAt`, `debounce`) и чистые функции — генератор id,
даты, форматирование.

`mcp.mjs` нужны вторые и не нужны первые: в Node нет `document`, и импорт всего файла
уронил бы процесс на первой же строке.

**Отступление от исходного пропозала.** Он предлагал имена `js/dates.js` + `js/dom.js`
и относил `uid` к DOM-половине. Это неверно: `uid` — данные, а не интерфейс, его зовут
`js/store.js` и `js/model.js` при создании задач и подзадач, и `mcp.mjs` он нужен ровно
затем же. Оставить `uid` в `js/dom.js` означало бы завести третью копию генератора id
в `mcp.mjs` — то самое, ради избавления от чего затевается разрез.

Поэтому: **`js/core.js`** — `uid`, `WEEKDAYS_SHORT`, `WEEKDAYS_FULL`, `MONTHS_GEN`,
`toDateStr`, `fromDateStr`, `todayStr`, `addDaysStr`, `nextMondayStr`, `isAllDay`,
`datePart`, `timePart`, `combineDue`, `parseDue`, `isOverdue`, `daysBetween`, `fmtDue`,
`fmtDayLabel`, `fmtDateShort`, `fmtTime`, `plural`, `oneLine`. **`js/dom.js`** — всё
остальное. Критерий разреза формальный и проверяемый: в `js/core.js` не встречается
ни `document`, ни `window`.

### Решение 5: `mcp.mjs` живёт в этом репозитории

Рядом с `serve.mjs`, который он вызывает, и рядом с `js/core.js`, который импортирует.
Отдельный репозиторий заставил бы синхронизировать `js/core.js` между двумя местами —
то есть вернул бы ровно ту проблему двух копий, от которой уходим.

Цена — `package.json` и `node_modules` в репозитории. Граница проводится жёстко и
проверяется: браузерная часть и `serve.mjs` не импортируют ничего из `node_modules`.

### Решение 6: `tf.py` выводится из строя, скилл переезжает на MCP целиком

Решение пользователя: одна копия логики вместо двух. `tf.py` удаляется, `SKILL.md`
в `~/Devel/agents-ensemble/skills/taskflow/` переписывается с CLI на MCP-инструменты.

Это правка в **другом репозитории** — она не попадает в коммиты этого change и требует
отдельного прохода. Порядок важен: сначала MCP работает и проверен, только потом удаляется `tf.py`.

Цена решения — потеря обхода корпоративного VPN (см. риски).

## Risks / Trade-offs

**Корпоративный VPN ломает доступ агента** → `tf.py` умел ходить в обход резолвера по
`TASKFLOW_IP`: под VPN домен `v864391.hosted-by-vdsina.com` не резолвится. MCP-клиент так
не умеет — он возьмёт адрес из конфига и упрётся в тот же неразрешимый домен. С выводом
`tf.py` из строя запасного канала не остаётся. Смягчение: строка в `/etc/hosts` на Mac,
записанная в `README` как обязательный шаг настройки под VPN. Проверить под VPN **до**
удаления `tf.py`, а не после.

**`serve.mjs` лежит — MCP отвечает ошибками на каждый вызов** → Агент получит стектрейс
вместо смысла. Смягчение: ошибки подключения к API оборачиваются в понятный текст
(«сервер синхронизации не отвечает»), это записано требованием в спеке.

**Спека MCP меняется** → Streamable HTTP заменил HTTP+SSE в 2025 году; следующая смена
транспорта потребует обновления SDK. Смягчение: изолированность `mcp.mjs` — обновление
затрагивает один файл.

**Разрез `util.js` задевает все модули сразу** → Импорты правятся в `js/ui.js`, `js/model.js`,
`js/store.js`, `js/moments.js`, `js/app.js`, `js/sync.js`; забытый импорт даёт белый экран.
Смягчение: `js/util.js` удаляется полностью, а не остаётся ре-экспортом — тогда забытый
импорт падает сразу и громко, а не тихо продолжает работать до следующего рефакторинга.

**`node_modules` в репозитории без сборки** → Легко случайно импортировать зависимость
в браузерную часть и сломать главное правило. Смягчение: проверка при выкатке — на чистой
копии без `npm install` должно подниматься `node serve.mjs` и полностью работать приложение.

**Два токена — второй способ потерять доступ** → Смягчение: генерация при первом запуске
в `data/mcp-token.txt`, чтобы токен всегда можно было прочитать на сервере.

## Migration Plan

1. Разрезать `js/util.js` на `js/core.js` и `js/dom.js`, поправить импорты во всех модулях,
   обновить `SHELL` и `CACHE` в `sw.js`. Проверить приложение — это самостоятельный шаг,
   ничего не ломающий.
2. Добавить `package.json`, `.gitignore` с `node_modules`, написать `mcp.mjs`.
3. Поднять локально, подключить MCP-клиента к `http://127.0.0.1:8788/mcp`, прогнать инструменты.
4. Выкатить на VPS: юнит `taskflow-mcp.service`, маршрут `/mcp*` в Caddy, перезапуск.
5. Подключить агента к `https://v864391.hosted-by-vdsina.com/mcp`, прогнать те же сценарии.
6. **Проверить под корпоративным VPN.** Если не работает — прописать `/etc/hosts` и проверить снова.
7. Только теперь: переписать `SKILL.md` на MCP и удалить `tf.py` в репозитории `agents-ensemble`.

**Откат:** остановить `taskflow-mcp.service` и убрать маршрут в Caddy — приложение и
синхронизация не заметят. Пока шаг 7 не сделан, `tf.py` остаётся рабочим запасным каналом.

## Open Questions

1. **Режим только для чтения.** Отдельный токен без права писать — отложен: сценария, где
   агенту нужно смотреть, но нельзя трогать, пока нет. Вернуться, если появится клиент,
   которому список отдаётся с меньшим доверием.
2. **Нужен ли `GET /mcp` с уведомлениями.** Появится смысл, когда список задач станет
   меняться со стороны (например, когда агент начнёт класть во «Входящие») и клиенту
   захочется узнавать об этом без опроса.
