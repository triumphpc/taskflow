## Context

TaskFlow — приложение без сборки: `index.html`, ES-модули в `js/`, `styles.css`, плюс
`serve.mjs` с `sync.mjs` на VPS. Запускается одной командой `node serve.mjs`, без
`npm install` и без зависимостей.

Интеграция с Google Calendar — единственное место, где это правило нарушено: браузерная
часть подтягивает Google Identity Services сторонним скриптом. Помимо `js/gcal.js` (447 строк)
интеграция размазана по четырём файлам: 53 упоминания в `js/ui.js`, 13 в `js/store.js`,
5 в `js/app.js`, 4 в `js/model.js`.

Эта работа — первая из трёх. За ней идут MCP-сервер и раздел «Входящие», и обе правят
`js/ui.js`, который сейчас разросся до 1496 строк. Удалять надо до них, а не после:
иначе те же 200 строк календарного кода придётся дважды тащить через конфликты слияния.

Ограничение, определяющее порядок работ: `eventId` созданных событий хранится **только**
в поле `task.gcal` внутри `data/taskflow.json`. Кода, который умеет их удалять, после этой
работы не останется.

## Goals / Non-Goals

**Goals:**

- Убрать интеграцию целиком — код, настройки, стили, документацию, внешнюю зависимость.
- Не оставить висящих событий в Google-календаре пользователя.
- Сохранить работоспособность приложения на старых данных, где `task.gcal` ещё лежит.
- Расчистить `js/ui.js` перед двумя следующими работами.

**Non-Goals:**

- Замена интеграции на что-либо другое. Просмотр встреч рядом с задачами — отдельная
  будущая работа на других условиях (чтение без записи), см. спеку `calendar-integration`.
- Миграция данных ради вычистки поля `task.gcal` из существующих записей.
- Изменение протокола синхронизации. `SCHEMA` остаётся `1`, маршруты `serve.mjs` не трогаются.

## Decisions

### Решение 1: Уборка в Google идёт до удаления кода

События календаря «TaskFlow» уже созданы, и связь с ними живёт только через `task.gcal.eventId`.
Если сначала удалить код, `normalizeTask` перестанет читать поле, приложение забудет про события,
и стереть их программно станет нечем — останется удалять руками по одному.

Порядок: убедиться, что синхронизация ничего не ждёт → удалить календарь «TaskFlow» в Google
целиком вместе с событиями → удалить OAuth Client ID в Cloud Console → и только теперь трогать код.

Альтернатива — написать одноразовый скрипт-чистильщик, который пройдёт по задачам и удалит
события через API. Отвергнута: это означает сохранить весь OAuth-путь ровно до того момента,
когда он больше не нужен, ради работы, которую в интерфейсе Google делает одна кнопка
«удалить календарь».

### Решение 2: Поле task.gcal не вычищается из данных

После удаления `normalizeTask` перестаёт читать `gcal`, и поле становится мёртвым довеском
в JSON. Слияние на сервере переносит записи целиком и на незнакомые поля не смотрит, так что
ничего не ломается. Поле уходит само при следующей правке задачи.

Альтернатива — миграция, поднимающая `SCHEMA` до `2` и переписывающая `data/taskflow.json`.
Отвергнута: цена (миграция, версия схемы, риск разъехавшихся клиентов на телефоне и Mac)
несопоставима с выгодой (несколько сотен байт мусора, который и так рассосётся).

### Решение 3: Раздел удаляется из навигации, а не прячется за настройкой

Флаг «скрыть календарь» оставил бы весь код на месте — а весь смысл работы в том, чтобы
кода не стало.

Следствие, которое нельзя упустить: горячие клавиши `1`…`5` привязаны к порядку разделов,
и `calendar` среди них. После удаления нумерация сдвигается, и обработчик в `js/app.js`
вместе с подсказками в настройках надо править согласованно — иначе клавиша будет открывать
не тот раздел.

### Решение 4: `CACHE` в `sw.js` поднимается с `taskflow-v10` до `taskflow-v11`

`js/gcal.js` уходит из `SHELL`. Без смены имени кеша service worker продолжит отдавать старую
оболочку, где модуль ещё импортируется, и приложение на телефоне встретит 404 на несуществующем
файле. Смена имени кеша — обязательная часть работы, а не косметика.

## Risks / Trade-offs

**Работа необратима на практике** → Откат кода — это revert коммита, но восстановление
интеграции потребует заново пройти Cloud Console: проект, включение Calendar API, OAuth consent
screen, scopes, test users, Client ID, разрешённые origins. Час работы минимум. Смягчение:
удаление календаря в Google (шаг 2 порядка работ) — последняя точка, до которой можно передумать;
до неё дошедший до Cloud Console шаг ещё ничего не разрушает.

**Расползание правки по `js/ui.js`** → 53 упоминания в файле на 1496 строк, часть из них —
одна строка внутри чужой функции (метки в строке задачи, восстановление при отмене очистки).
Пропущенный кусок даст `ReferenceError` на `G` уже после удаления модуля. Смягчение: финальная
проверка `grep -ri "gcal\|google" js/ index.html styles.css sw.js` должна возвращать пусто.

**Телефон на старом кеше** → До обновления service worker телефон живёт старой оболочкой,
которая импортирует удалённый `js/gcal.js`. Смягчение: поднятый `CACHE` заставляет обновиться;
проверить на телефоне после выкатки, а не только в браузере на Mac.

**Пользователь ждёт, что события в Google останутся** → После удаления календаря в Google
исчезнут и события, которые TaskFlow туда экспортировал; если какие-то из них воспринимались
как настоящие встречи, они пропадут. Смягчение: перед шагом 2 просмотреть календарь «TaskFlow»
глазами и перенести нужное в основной календарь.

## Migration Plan

1. **Подготовка в Google (до кода).** Открыть приложение с включённой синхронизацией,
   дождаться, что ничего не ждёт отправки. Просмотреть календарь «TaskFlow» глазами.
2. **Удалить календарь «TaskFlow»** в Google Calendar целиком, вместе с событиями.
3. **Удалить OAuth Client ID** в Cloud Console (или весь проект `taskflow`).
4. **Удалить код** — файл, разделы, настройки, стили, документация.
5. **Поднять `CACHE`** в `sw.js` до `taskflow-v11`, убрать `js/gcal.js` из `SHELL`.
6. **Проверить** на Mac и на телефоне: приложение открывается, разделы переключаются
   клавишами, старые задачи с полем `gcal` живы.

**Откат:** revert коммита возвращает код, но не возвращает OAuth-приложение и календарь
в Google — их придётся создавать заново вручную.
