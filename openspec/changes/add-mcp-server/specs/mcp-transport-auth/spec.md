## ADDED Requirements

### Requirement: Транспорт — Streamable HTTP на одном маршруте

Сервер SHALL обслуживать MCP по маршруту `POST /mcp` транспортом Streamable HTTP.

`GET /mcp` — поток серверных уведомлений по SSE — SHALL отвечать `405`, пока уведомлений
нет. Это осознанная заглушка, а не недоделка: подписка появится, когда появится, что слать.

#### Scenario: Клиент подключается

- **WHEN** MCP-клиент открывает сессию на `POST /mcp` с корректным токеном
- **THEN** сервер отвечает по протоколу и отдаёт список инструментов

#### Scenario: Запрос потока уведомлений

- **WHEN** клиент выполняет `GET /mcp`
- **THEN** сервер отвечает `405`

### Requirement: Доступ по Bearer-токену, отдельному от токена синхронизации

Сервер SHALL требовать заголовок `Authorization: Bearer <token>`. Токен SHALL браться из
`TASKFLOW_MCP_TOKEN`, иначе из `data/mcp-token.txt`, иначе генерироваться при первом запуске.

Сравнение токена MUST выполняться в постоянное время — как это уже сделано в `sync.mjs`.

MCP-токен SHALL быть независим от токена синхронизации: ротация MCP-токена отзывает доступ
агенту и MUST NOT затрагивать браузер на телефоне и на Mac.

#### Scenario: Запрос без токена

- **WHEN** приходит запрос на `/mcp` без заголовка `Authorization`
- **THEN** сервер отвечает `401`

#### Scenario: Ротация отзывает доступ только у агента

- **WHEN** MCP-токен заменён на новый
- **THEN** агент со старым токеном получает `401`
- **AND** приложение в браузере продолжает синхронизироваться без вмешательства

### Requirement: Отклонение от OAuth 2.1 зафиксировано письменно

`README` SHALL содержать явное указание, что предлагаемый спекой MCP для HTTP-транспорта
OAuth 2.1 сознательно не реализован, и причину: для инструмента на одного пользователя это
лишний слой, поэтому взят Bearer-токен.

Запись нужна, чтобы через полгода не гадать, почему сделано не по спеке, и чтобы решение
можно было пересмотреть осознанно.

#### Scenario: Чтение документации

- **WHEN** читатель `README` доходит до раздела про MCP
- **THEN** он находит указание, что OAuth 2.1 сознательно не реализован, и причину

### Requirement: Сервер слушает только петлевой интерфейс и проверяет Origin

Процесс SHALL слушать `127.0.0.1` и MUST NOT принимать соединения напрямую снаружи.
Наружу маршрут выводит Caddy.

Сервер SHALL проверять заголовок `Origin` — прямая рекомендация спеки MCP против
DNS rebinding.

#### Scenario: Прямое обращение снаружи

- **WHEN** запрос приходит на порт 8788 в обход Caddy с внешнего адреса
- **THEN** соединение не устанавливается

#### Scenario: Запрос с чужим Origin

- **WHEN** приходит запрос с заголовком `Origin`, не входящим в разрешённые
- **THEN** сервер отклоняет запрос

### Requirement: Приложение остаётся запускаемым без установки зависимостей

Зависимость `@modelcontextprotocol/sdk` SHALL использоваться только в `mcp.mjs`.

`index.html`, `js/`, `styles.css` и `serve.mjs` MUST NOT импортировать ничего из
`node_modules`. Команда `node serve.mjs` SHALL работать на чистой копии репозитория
без `npm install`.

#### Scenario: Запуск на чистой копии

- **WHEN** репозиторий склонирован и `npm install` не выполнялся
- **THEN** `node serve.mjs` поднимается и отдаёт приложение
- **AND** браузерная часть работает полностью

#### Scenario: Запуск MCP без зависимостей

- **WHEN** `node mcp.mjs` запускается без `npm install`
- **THEN** процесс сообщает, что нужно выполнить `npm install`, понятным текстом
